# PRD 보완 정리와 수정 제안 (2026-10-22)

PRD(2026.10.15)를 멘토 피드백과 **현재 구현 상태**에 맞춰 점검한 결과입니다. 이 문서를 보면서 PRD를 고치면 됩니다.

- **읽는 법**: 위치는 PRD PDF의 **쪽 번호**입니다. "제안 문구"는 PRD 문체(~한다)에 맞춰 써 둔 것이라 그대로 붙여넣어도 됩니다. 사실관계(숫자, 동작)는 2026-10-22 기준 코드와 설정에서 확인한 값입니다.
- **먼저 볼 곳**: 1장(피드백 반영 상태) → 2장(PRD 안에서 서로 어긋난 곳) → 6장(팀이 정해야 하는 것).
- 모르는 값은 추측하지 않고 "확인 필요"로 적었습니다.

## 0. 한눈에 보기

| 멘토 피드백 항목 | PRD 반영 상태 | 남은 일 |
| --- | --- | --- |
| ① 타깃 사용자·사용 상황 | **대부분 반영** | 5쪽 표의 행 이름이 뒤바뀜, 멘토가 제안한 "보험사 비율 입력" 검토 결과가 없음 |
| ② 모델 성능 평가 기준 | **대부분 반영** | 평가 영상 수가 `○○`로 비어 있음, 7개 유형 숫자가 낡음, 모델 선정 기준 없음 |
| ③ 분석 결과와 산정 로직 연결 | **부분 반영** | **"사용자가 수정하면 어느 단계부터 다시 계산하나"가 없음**, 2단계 출력 예시가 구현과 다름 |

| ⑤ 판단 근거의 적합성·신뢰성 | **부분 반영** | 판례를 고르는 **조건·우선순위·근거 부족 시 처리**가 PRD에 없음 (구현에는 있음) |

## 1. 멘토 피드백 항목별 점검과 수정 제안

### ① 타깃 사용자 및 주요 사용 상황 구체화 (PRD 5~6쪽)

**잘 된 점**: 상황 1(보험사 안내 전 확인)을 핵심으로, 상황 2(안내 비율이 예상과 달라 기준 확인)를 보조로 나눴고, "보험사 비교는 제공하지 않는다, 대신 산정 과정을 공개해 직접 대조하게 한다"는 이유를 적었습니다(7쪽).

**고칠 점**
1. **5쪽 표의 행 이름이 서로 바뀌었습니다.** "제공하는 것" 행에는 사용 상황 문장이, "제공하지 않는 것" 행에는 실제로 제공하는 기능(예상 과실비율, 판단 근거, 관련 판례, 단계별 산정 과정, 미반영 가감요소 표시)이 들어 있습니다. 행 이름을 "사용 상황"과 "제공하는 것"으로 바꾸고, 진짜 "제공하지 않는 것"(보험사 비율과의 직접 비교, 차이 원인 판단)을 새 행으로 추가합니다.
2. 멘토가 제안한 "사용자가 보험사 비율을 직접 입력하면 서비스가 산정한 기본과실·가감요소와 함께 보여주는 방안"을 **채택할지 보류할지** 적어야 합니다. 지금은 아무 언급이 없어서 멘토가 "검토 안 했다"고 볼 수 있습니다.

**제안 문구 (5쪽 표 아래에 추가)**
> 상황 2의 사용자는 보험사가 안내한 비율과 서비스가 산정한 기본과실·가감요소를 **직접 대조**할 수 있다. 서비스는 보험사의 판단을 평가하거나 대체하지 않으며, 보험사는 영상 외 자료(진술, 현장 조사)까지 반영하므로 차이의 원인을 판단하지 않는다. 사용자가 보험사 비율을 입력해 나란히 보여주는 기능은 **확장 기능으로 보류**하고, 보험사 판단과의 비교와 차이 원인 분석이 가능한지는 별도로 검증한다.

(팀 결정 필요: 6장 1번)

### ② 모델 성능 평가 기준 구체화 (PRD 4~5쪽, 17쪽)

**잘 된 점**: 평가 데이터 구성(장소별 비율 46/39/21/17/5/5), 정답 라벨 기준 표, 지표별 계산 방법과 목표치, 데이터 분리 기준, 한계가 모두 들어갔습니다.

**고칠 점**
1. **평가 영상 수가 비어 있습니다.** 4쪽 2항 "개발에 쓰지 않은 `○○`개", "유형별 `○`개 이상"이 미정이고, 17쪽 데이터 표에는 "(미정) 3개"가 적혀 있어 서로 다릅니다. 숫자를 정하거나, 못 정하면 "현재 라벨이 있는 영상은 N개이며 확정 전"이라고 적습니다.
2. **"가감요소가 적용되는 7개 유형"(4쪽)은 낡았습니다.** 현재 가감요소를 묻는 유형은 116개입니다(4장 3번 참고). 평가 구성의 기준을 현재 상태로 다시 정해야 합니다.
3. **라벨 영상 한계를 더 구체적으로**: 현재 정답 라벨 영상은 주차장 9개(유형 126·127)뿐입니다(4쪽). 신호 교차로, 직선 도로 등 나머지 장소는 **라벨이 0개라 정확도를 측정할 수 없다**고 한계(5쪽)에 명시하는 게 좋습니다.
4. **테스트 절차**: 계산 방법은 있지만 "누가, 언제, 어떤 도구로, 결과를 어디에 기록하나"가 없습니다. 저장소에는 라벨 영상 평가 도구(`backend/tools/evaluate_labels.py`)와 라벨 검수 페이지가 있으니 연결해서 한 줄 적습니다.
5. **목표치의 근거**: 90/70/50/80%가 임시 목표인지 근거가 있는 값인지 표시합니다. 임시라면 "모델 선정 후 확정(임시)"로 적는 편이 솔직합니다.
6. **모델 선정 기준이 없습니다.** 4쪽 지표가 "모델 선정 후 확정"인데, 어떤 모델 후보를 어떤 기준으로 비교해 고르는지가 없습니다. 지금 영상 관찰 모델을 `gpt-4.1`에서 `gpt-6.1-sol`로 올려 시험 중이므로 "후보 모델 / 동일 평가셋 / 비교 지표 / 비용 상한"을 한 표로 넣으면 됩니다.
7. 이해도 평가 인원이 4쪽·5쪽은 "5명", 19쪽 리스크 표는 "3~5명"으로 다릅니다.

**제안 문구 (6. 한계에 추가)**
> 현재 정답 라벨이 있는 영상은 주차장 9개(유형 126·127)뿐이다. 신호 교차로, 비신호 교차로, 직선 도로, T자형, 회전교차로는 정답 라벨이 없어 해당 장소의 정확도는 측정하지 못하며, 확보 전까지 이 장소의 지표는 "측정 불가"로 표기한다.

### ③ 영상 분석 결과와 과실비율 산정 로직의 연결 (PRD 16~17쪽)

**잘 된 점**: 17쪽에 7단계 데이터 흐름 표(전처리 → 사고 상황 인식 → 사고 상황 확정 → 인정기준 매핑 → 가감요소 적용 → 근거 설명 → 판례 조회)와 2단계 출력 예시가 들어갔습니다.

**고칠 점**
1. **가장 중요: "사용자 수정 반영: 어떤 단계부터 재계산하는지"가 없습니다.** 멘토가 특히 명확히 정의해 달라고 한 항목입니다. 구현 기준으로 쓸 수 있는 문구가 아래에 있습니다.
2. **2단계 출력 예시가 구현과 다릅니다.** 예시의 `confidence: high/mid/low`, `accident_type: "측면 충돌"`, `observed_modifiers.code: "M03"` 형식은 실제로 쓰지 않습니다. 실제는 3장 1~3번을 보세요.
3. **가감요소 적용 단계에 "쉬운 문장 검수가 끝난 요소만 쓴다"는 규칙이 없습니다.** 이 규칙 때문에 결과가 "확정"이 아니라 "일부 반영"으로 나오는 경우가 많습니다(4장 3번).

**제안 문구 (17쪽 "라. 과실 산정 데이터 흐름" 아래에 추가)**
> **사용자 수정 반영**: 사용자가 3단계(사고 상황 확정)에서 AI가 고른 장소, 사고 유형, 내 차 움직임, 상대 차 움직임 중 일부를 바꾸면, **영상 분석(2단계)은 다시 하지 않고** 확정된 항목으로 4단계(인정기준 매핑)부터 다시 계산한다. 사용자가 확정한 사고 유형·역할에 따라 기본과실, 가감요소 질문, 법령 풀이, 유사 판례가 모두 새로 정해진다. 반면 영상에서 뽑은 **타임라인과 사고 요약은 AI가 본 그대로** 유지되므로, 사용자가 고른 움직임이 AI 관찰과 어긋나면 결과 화면과 타임라인 화면에 "고르신 상황이 AI가 영상에서 본 내용과 달라요. 타임라인과 요약은 참고용으로만 봐 주세요"를 표시한다.

### ④ 판단이 불확실한 상황의 처리 기준 (PRD 10~11쪽 예외 흐름, 8쪽 결과 상태)

**잘 된 점**: 결과를 **확정 / 일부 반영 / 기본 비율만 / 확정 불가** 4가지로 구분했고(8쪽), "사고 유형을 정할 수 없으면 과실비율을 제시하지 않는다"고 적었습니다. 이 4가지는 구현의 결과 상태(`final` / `partial` / `base_only` / `unresolved`)와 일치합니다.

**고칠 점**: 예외 흐름 표(10~11쪽)가 상황마다 한 줄이라, 멘토가 요구한 **구분**이 드러나지 않습니다. 아래 표처럼 "판단 기준 → 시스템 처리 → 사용자에게 보이는 것"으로 풀어 쓰는 것을 제안합니다. **현재 구현 기준 내용**을 적어 두었으니 PRD와 맞는지 팀이 확인해 주세요.

| 상황 | 판단 기준 | 시스템 처리 (현재 구현) | 사용자에게 보이는 것 |
| --- | --- | --- | --- |
| 지원하지 않는 사고(차대차 아님) | AI가 보행자·이륜차·자전거로 **명확히** 판단했을 때만 (불확실하면 계속 진행) | **분석을 종료**한다. 영상은 저장 동의와 관계없이 24시간 안에 삭제 | "분석할 수 없는 영상이에요" + 차대차만 분석한다는 안내 + "다른 영상 올리기" |
| 영상 길이 초과 | 비식별 영상 기준 20초 초과, AI 호출 **전에** 확인 | 분석 종료(실패 `VIDEO_TOO_LONG`) | "영상이 너무 길어요" + 사고 전후만 잘라 다시 올리라는 안내 |
| 영상 분석 실패(오류) | AI 호출 오류, 응답 형식 오류, 키 미설정 등 | 실패로 기록하고 종료. 응답 없는 작업은 **30분 뒤 다시 등록**, 시도 **2회**를 넘으면 실패 처리 | 실패 안내 + "다른 영상 선택" (현재 화면에서 같은 영상 재분석 버튼은 없음) |
| 사고 유형 분류 불확실 | AI가 확정한 후보가 없을 때 | **참고 후보를 최대 3개** 보여 주되 미리 선택하지 않는다. 후보들이 같은 장소를 가리키면 장소만 미리 선택 | "AI가 확신하지 못했어요" + 후보 칩 + 장소→유형→내 차→상대 차 직접 선택 |
| 맞는 유형 없음 | 사용자가 "맞는 사고 유형이 없어요"를 선택 | 가감요소·비율 없이 상황 설명만 | "과실 비율을 안내할 수 없어요" + 가까운 유형(참고용) |
| 분석 결과가 실제와 다름 | 사용자가 확인 화면에서 판단 | 4항목을 직접 수정(AI 재분석 없음). 4장 2번의 불일치 안내 | 수정한 값으로 비율·판례가 바뀜, 타임라인은 참고용 안내 |
| 일부 가감요소를 쓸 수 없음 | 쉬운 문장 검수가 끝나지 않은 가감요소 | 그 요소는 묻지도 계산하지도 않음 | "확인한 요소만 반영한 비율" + 반영하지 않은 가감요소 개수 안내 |

**결정이 필요한 것** (PRD 19쪽 리스크 대응 2번은 "분류 확신도가 기준보다 낮으면 결과를 확정하지 않고 후보를 제시"라고 쓰는데, **구현에는 확신도 숫자나 기준값이 없습니다.** 지금은 "AI가 확정한 후보가 있느냐 없느냐"로만 나눕니다.) → 6장 5번

### ⑤ 판단 근거의 적합성 및 신뢰성 확보 (PRD 8~9쪽, 12~13쪽 FR-AI-010~012)

**잘 된 점**: 판례를 DB에서 먼저 찾고 없으면 법령 API로 보완하고, 최대 3개를 보여주며 일부만 맞으면 "일부 일치"로 표시한다고 적었습니다. 판례 비교만 AI가 쓰고 판결문 인용 확인과 2차 검증을 통과한 것만 보여준다는 점도 들어갔습니다(9쪽).

**고칠 점**: 멘토가 물은 4가지 중 **적용 조건, 우선순위, 근거 부족 시 처리**가 PRD에 없습니다. 구현 문서(`docs/api.md`의 "판례 규칙"과 "판례 비교 방식")에 이미 있는 내용이라 옮겨 적으면 됩니다.

**제안 문구 (FR-AI-012 설명 또는 별도 항목으로 추가)**
> **판례 선정 기준**: 확정된 사고 유형에 연결된 판례 중, 사고 유형뿐 아니라 장소와 내 차·상대 차의 진행 조건이 얼마나 맞는지를 기준으로 고른다. **우선순위**는 ① 손해보험협회 도표에 등록된 판례 → ② 조건이 모두 맞는 법령 API 판례 → ③ 조건이 일부만 맞는 판례 순이며, 최대 3개를 보여 준다. 일부만 맞으면 몇 개 조건이 맞았는지 함께 표시한다. **조건이 전혀 맞지 않는 판례로는 개수를 채우지 않으므로** 3개보다 적거나 0개일 수 있으며, 적합한 판례가 없으면 "판례가 없음"과 판단의 한계를 안내한다. 판례 본문이 충분한 경우에만 AI가 사고와의 공통점·차이점을 쓰고, 판결문 인용이 실제 본문에 있는지와 2차 검증을 통과한 항목만 보여 주며, 통과하지 못하면 규칙 기반 비교로 대신한다. 속도, 판례 유사도 퍼센트처럼 근거를 만들 수 없는 값은 보여 주지 않는다.
