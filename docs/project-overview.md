# Avly 프로젝트 전체 정리

> 2026-10-20 기준. 기능이 어떻게 만들어져 있는지, 어떤 기술을 쓰는지, 어디까지 되었는지, 사람이 검수해야 할 것, DB에 무엇이 저장되는지를 한 곳에 모았습니다.
> 새로 정한 내용이 아니라 기존 문서(README, `docs/`)와 코드(`backend/app`, `backend/migrations`)를 읽고 정리한 것입니다. 자세한 근거는 각 절의 링크를 보세요.

상태 표시: ✅ 구현됨 · 🟡 일부만 됨 · ⬜ 미구현 · ⚠️ 사람 검수 필요 · ❓ 실제 환경에서 검증 못 함

## 1. 서비스 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 한 줄 정의 | 블랙박스 영상을 AI로 분석해 과실비율을 안내하는 서비스 |
| 지원 사고 | **차대차 사고만.** 손해보험협회 과실비율 인정기준 133개 유형 |
| 지원하지 않는 사고 | 보행자, 이륜차, 자전거. 분석을 멈추고 "지원하지 않는 사고"로 안내 (오류가 아님) |
| 영상 | 사고마다 1개, 사고 전후 약 15초(상한 20초), mp4/mov/avi |
| 결과의 성격 | 법적 효력이 없는 AI 참고 자료 |
| 로그인 | 없음. 사고를 만들 때 받은 `session_id`가 소유 토큰 |

**사용자 흐름**

```
영상 선택 → 분석 동의(필수) [+ 저장·활용 동의(선택)]
→ 번호판·사람 비식별화 → AI 분석
→ 사고 상황 확인 (장소 / 유형 / 내 차 / 상대 차) → 가감요소 질문
→ 결과(과실비율, 가감 근거) → 사고 타임라인 → 유사 판례
```

## 2. 기술 아키텍처

```
 브라우저 (React, :5173)
     │  HTTP + X-Session-Id
     ▼
 backend (FastAPI, :8000) ──── 영상 파일 저장 (backend/uploads)
     │  분석 요청을 job 표에 넣음
     ▼
 PostgreSQL ◀──── 상태·결과·job을 읽고 씀 ────▶ worker (한 번에 한 작업)
                                                  │
                    ┌─────────────────────────────┼────────────────────────┐
                    ▼                             ▼                        ▼
           비식별화 (YOLO)              avly 분석 모델 (OpenAI GPT-4.1)   판례·법령 API + 판례 AI 비교
        번호판 검은 박스, 사람 블러      영상 장면 이미지 → 사고 상황       (OpenAI gpt-4.1-mini, 글자만 전송)
```

| 구성 | 기술 | 하는 일 | 위치 |
| --- | --- | --- | --- |
| 프론트엔드 | React, Vite, 폴링으로 상태 조회 | 5개 화면(소개, 업로드, 결과, 타임라인, 판례) | `frontend/src` |
| 백엔드 API | FastAPI | 요청 접수, 조회, 서명된 영상 URL. **분석은 직접 하지 않음** | `backend/app` |
| worker | 같은 코드의 별도 프로세스 | DB `job` 표를 보고 비식별화, 분석, 결과 계산, 만료 영상 삭제 | `backend/app/worker` |
| DB | PostgreSQL 17, 순수 SQL 마이그레이션 | 사고, 영상, 분석, 판례, 작업 대기열 | `backend/migrations` |
| 분석 모델 | `avly` 패키지, 프롬프트와 데이터는 파일 | 영상 분석 → 과실표 유형 비교 → 규칙 계산 | `backend/model/avly` |
| 비식별화 | YOLO 번호판·사람 탐지 | 번호판 검은 박스, 사람 전체 블러. 실패하면 영상을 만들지 않고 멈춤 | `backend/plate` |
| 외부 서비스 | OpenAI, 국가법령정보 API(`law_api`) | 영상 분석, 판례 비교 설명, 판례·법령 조회 | |

**설계 특징**
- **API와 worker 분리**: 분석은 오래 걸리고 모델이 전역 상태를 쓰기 때문에, API는 `job` 표에 일을 넣기만 하고 worker가 한 번에 하나씩 처리합니다.
- **엔진 3종**: `fake`(키 없이 전체 흐름 시험, 기본값), `replay`(저장 결과 재생), `avly`(실제 분석). 개발 기본값은 가짜 분석과 비식별 없는 복사라 실제 AI 분석이 아닙니다.
- **과실표와 가감요소는 DB가 아니라 저장소 파일**(`fault_table_car_to_car.csv`, `adjustment_rules.json`)로 관리하고, DB에는 유형 번호(`accident_type_id`)만 저장합니다.
- **공용 DB 사용**: `DATABASE_URL` 한 줄로 팀 공용 DB(Supabase)와 로컬 DB를 고릅니다. 작업과 영상에 PC 이름표를 붙여 서로의 작업을 가져가지 않고, 공용 DB 마이그레이션은 자동으로 적용하지 않습니다.
- **분석 상태**: `queued → processing(5단계) → awaiting_confirmation → (확정) → processing(finalize) → completed`. 끝나지 않는 경우는 `unsupported`, `failed`.

## 3. 기능별 설명과 진행 상태

| # | 기능 | 어떻게 동작하나 | 상태 | 검수·남은 일 |
| --- | --- | --- | --- | --- |
| 1 | 영상 업로드 | 사고당 영상 1개, 확장자·크기 확인 후 저장. 길이는 분석 시작 때 확인 | ✅ | 화면은 "50MB 권장", 서버 상한은 200MB로 **불일치**. 길이를 업로드 전에 볼지 미정 |
| 2 | 동의 | 분석 동의(필수), 저장·활용 동의(선택), "내 차가 직접 관여한 영상" 확인(필수). 동의 시각과 문서 버전을 저장 | ✅ ⚠️ | **문구는 AI 초안.** 법무 검토 전 (외부 AI 전송, 국외 이전, 보관 기간) |
| 3 | 번호판·사람 비식별화 | 프레임마다 탐지해 번호판은 검은 박스, 사람은 전체 블러. 비식별본으로만 분석 | ✅ ❓ | worker 이미지 안의 실제 YOLO 동작은 미검증. 멀거나 어두운 대상은 놓칠 수 있어 **누락률 표본 검수** 필요 |
| 4 | AI 분석 | 전체 흐름 → 사고 전후 상세(필요할 때만) → 차선 원인 → 유형 비교. 영상 1건당 AI 최대 4회 | ✅ ❓ | **실제 GPT 분석은 정확도를 측정한 적 없음.** 정답 라벨이 있는 평가 영상이 없음. 10초 영상 시험에서 약 66초 |
| 5 | 지원하지 않는 사고 안내 | 차대차가 아니면 분석을 멈추고 `unsupported`. 영상은 24시간 뒤 삭제 | ✅ | 오판(차대차를 보행자로 판단) 시 되돌릴 방법 미정 |
| 6 | 사고 상황 확인 | 장소 → 유형 → 내 차 → 상대 차를 단계별로 고름. 값을 고치면 영상은 다시 분석하지 않고 규칙 계산만 다시 함 | ✅ | 단계별이 좋은지 한 장 카드가 좋은지 미정 |
| 7 | 가감요소 질문·계산 | 질문에 답하면 규칙으로 과실비율 가감 | 🟡 ⚠️ | **133개 유형 중 122개 등록(약 92%)** — 기존 7개 + PDF에서 뽑은 115개(전부 검수 전). 막힌 11개 유형은 "기본 비율만" 안내. 숫자가 틀리면 비율이 틀리므로 사람 검수 필수 |
| 8 | 쉬운 말 설명 | AI 없이 미리 써 둔 문장. 가감요소 20개, 법령 풀이 | 🟡 ⚠️ | **전부 검수 전.** 법령 풀이 7개는 비어 있음 ([easy-words-review.md](review/easy-words-review.md)) |
| 9 | 결과 화면 | 결과 상태 4종: 확정 / 기본값만 / 후보 여러 개 / 확정 불가 | ✅ | 4가지 상태의 디자인 확정 필요 |
| 10 | 사고 타임라인 | 구간(시작~끝 초), 설명, 확실도, 근거 문장. 속도·G값·충돌 확정은 **보여주지 않음** | ✅ | 영상을 보관하지 않으면 사용자가 자기 파일을 다시 선택해 재생 |
| 11 | 유사 판례 | DB 먼저 조회, 없으면 법령 API로 가져와 저장. 상위 3건, 부족하면 일부 일치 판례로 채움 | ✅ ❓ | 실제 `law_api`로는 확인했으나 사고와 무관한 판례가 섞임(검색 한계) |
| 12 | 판례 AI 비교 | 판결문 인용을 붙여 개요·판단 요지·공통점·차이점을 작성. 서버가 인용 확인 + 2차 AI 검증, 결과는 DB에 저장해 재사용. 안 되면 규칙 비교 | ✅ ⚠️ | 인용은 맞아도 의미가 어긋난 설명이 남을 수 있음. **유형별 10건 이상 사람이 읽고 검수** ([case-compare-review.md](review/case-compare-review.md)) |
| 13 | 세션 만료와 영상·결과 삭제 | 세션 2시간. 지나면 분석 결과 삭제(조회 즉시 410), 원본·비식별본 삭제. 저장 동의 시 비식별본과 분석 결과를 90일 보관. 차대차 아닌 영상은 24시간. 화면에 자동 삭제 시각과 **결과 지우기** 버튼. 동의 화면에 **전체 동의** 버튼 | ✅ ⚠️ | 동의 문구가 새 정책을 반영했는지 법무 확인 필요. 만료 직전 알림은 없음 |
| 14 | 결과 PDF | 브라우저 인쇄로 PDF 저장. 서버 PDF(`POST .../reports`)는 501 | ⬜ | 서버 PDF가 필요한지 결정 |
| 15 | 결과 공유 | 소유 토큰이 없으면 못 봄 | ⬜ | 공유 기능 유지 여부, 공유할 정보 범위 미정 |

**제거된 기능**: 영상 증거(타임라인과 중복), 퀴즈, 사전 설문, 텔레메트리.

### 우선순위 (기존 문서 기준)
1. 평가용 영상 10~20개와 정답 라벨 (모델 교체 판단과 품질 보증의 전제)
2. 가감요소 확장 범위와 검수자
3. 동의 문구 법무 확인
4. 결과 4가지 상태 디자인
5. 영상 보관 기간과 세션 정의

### 문서끼리 어긋나는 곳 (이번에 읽으면서 발견)
- [prd-reference.md](prd-reference.md) §3 표는 "저장 동의 화면 없음", "비식별화 서비스 흐름에 미연결", "사고 상황 확인 화면 미구현"으로 적혀 있지만, 같은 문서 §10과 [team-review.md](team-review.md)는 모두 구현·연결됐다고 적혀 있습니다. §3 표가 오래된 것으로 보입니다.
- [consent-review.md](review/consent-review.md)의 동의 문구 위치(`frontend/src/components/home/ConsentModal.jsx`)는 현재 `frontend/src/pages/home/components/ConsentModal.jsx`입니다.
- 백엔드 테스트 수가 108개(prd-reference)와 109개(team-review)로 다릅니다.
- [prd-reference.md](prd-reference.md) §6의 "업로드 폴더 전체가 열려 있음"은 현재 서명 URL(`security.py`, `routers/media.py`)이 있어 해소된 것으로 보이나, 이 문서를 쓰면서 확인하지는 못했습니다.

## 5. DB: 기능별로 무엇이 저장되나

마이그레이션 3개(`0001_initial`, `0002_job`, `0003_case_ai`)에 테이블 11개가 있습니다. 설계 배경은 [schema-v0.4-proposal.md](db/schema-v0.4-proposal.md), 실제 스키마는 `backend/migrations/`입니다.

### 5-1. 기능 → 테이블

| 기능 | 테이블 | 저장되는 것 |
| --- | --- | --- |
| 사고 생성·동의 | `accident` | 제목, 상태, **`session_id`(소유 토큰)**, 동의 문서 버전, 분석 동의 시각, 저장·활용 동의 시각(없으면 NULL), 세션 만료 시각 |
| 영상 업로드 | `video` (`kind=original`) | 저장 키(URL이 아님), 해시, 크기, 만료 시각. 사고당 원본 1개만 허용 |
| 비식별화 | `video` (`kind=masked`) | 원본과의 연결(`source_video_id`), 비식별본 저장 키, 길이·해상도, **탐지 통계**(처리 프레임 수, 번호판·사람 탐지 프레임 수와 횟수). 만료 시각은 저장 동의가 있으면 NULL(무기한) |
| 분석 요청·진행 | `analysis`, `job` | 분석 상태, 현재 단계(`stage`), 시도 횟수, 시작·종료 시각. `job`에는 작업 종류(`analyze`/`finalize`), 상태, 잠금 시각, 오류, **이 PC의 이름표** |
| AI 분석 결과 | `analysis.scene` (JSONB) | 사고 상황 요약, 도로 형태, 내 차·상대 차 행동, 접촉 여부, 후보 유형 목록, 타임라인, 충돌 시점. **사용자 확인과 재계산에 쓰는 중간 결과** |
| AI 호출 기록 | `analysis_stage_log` | 단계, 공급자, 모델, 입력·출력 토큰, 캐시 여부, 지연(ms), 성공 여부. **건당 AI 비용 계산의 근거** |
| 지원하지 않는 사고 | `analysis` | `status=unsupported`, `unsupported_reason` |
| 실패 | `analysis` | `error_code`, `error_message` (사용자에게 보여줄 한국어 문구) |
| 사고 상황 확인·가감요소 답 | `analysis.confirmed` (JSONB) | 사용자가 확정한 유형 번호, 역할(내 차가 표의 A/B 중 어느 쪽인지), **가감요소 답변** |
| 결과 계산 | `analysis.result` (JSONB), `accident_type_id`, `fault_me`, `fault_other` | 결과 상태, 기본 비율, 가감 단계, 적용된 가감요소, 법령 조문, 타임라인, 관련 판례와 비교, 고지 문구. 비율은 **확정되지 않으면 NULL** |
| 재현성 | `analysis` | 영상 해시, **과실표 파일 해시**(`csv_sha256`), 분석 코드 버전(`pipeline_version`) |
| 판례 저장 | `legal_case` | 법원, 선고일, 사건번호, 요약, 판례에 소개된 비율(원문), 출처 종류·URL, **사람 검수 여부**(`verified`, 검수자, 검수 시각), API 원본 응답 |
| 판례 ↔ 유형 연결 | `case_accident_type` | 유형 번호, 판례, 관련도 상태, "이 판례를 그대로 적용하면 안 되는 이유" |
| 판례 조회 기록 | `case_lookup` | 유형별 조회 상태, 찾은 건수, **다음 조회 가능 시각**(API 반복 호출 방지) |
| 판례 AI 비교 | `case_ai` | 캐시 키(판례 본문 + 사고 상황 + 프롬프트 버전 + 모델), 검증 통과한 비교 결과, 토큰 수 |

### 5-2. 저장되지 않는 것
- **프레임 이미지**: 저장하지 않습니다. 결과에는 프레임 번호와 초 단위 시각만 담고, 장면은 보관한 영상에서 뽑습니다.
- **과실표·가감요소 규칙**: DB가 아니라 저장소 파일입니다.
- **로그인 정보·개인 식별 정보**: 없습니다. 소유 토큰(`session_id`)만 있습니다. 동의는 시각과 문서 버전만 기록하고 IP나 기기 정보는 기록하지 않습니다.
- 외부 AI에는 비식별 영상의 장면 이미지가 나가며(판례 비교는 글자만), 우리 서버에는 저장하지 않습니다.

### 5-3. 보관·삭제 시점

| 데이터 | 언제 지워지나 | 비고 |
| --- | --- | --- |
| 원본 영상 파일 | 세션 만료(기본 2시간, `SESSION_TTL_HOURS`) | worker가 1분마다 확인해 파일 삭제, DB에는 `deleted_at`만 남김 |
| 비식별본 (저장 동의 **없음**) | 세션 만료 시 | |
| 비식별본 (저장 동의 **있음**) | 90일 (`RETENTION_DAYS`) | 사용자에게는 다시 보여 주지 않음 |
| 차대차가 아닌 영상 (원본·비식별본) | 24시간 (`UNSUPPORTED_RETENTION_HOURS`) 또는 세션 만료 중 빠른 쪽 | 저장 동의와 무관 |
| 분석 결과 (`scene`, `confirmed`, `result`, 과실비율), 저장 동의 **없음** | 세션 만료 시 DB에서 삭제 | 조회는 만료 즉시 `410`. '결과 지우기'로 즉시 삭제 가능 |
| 분석 결과, 저장 동의 **있음** | 비식별 영상과 같은 90일 | 사용자에게는 보여 주지 않고 보관만 함. 데이터셋 용도(AI가 본 것 + 사용자가 고친 값 = 정답 라벨) |
| 사고 제목(업로드 파일 이름) | 세션 만료 시 | 개인정보가 들어갈 수 있어 동의와 상관없이 삭제 |
| 사고 행, AI 호출 기록 | 남김 | 개인정보 없음. 저장 동의 영상이 사고 행을 참조하고, 호출 기록은 비용 계산에 필요 |
| 완료된 `job` 행 | 지우지 않음 | 쌓이기만 함 |
| 판례, 판례 비교 | 계속 보관 | 공개 자료와 캐시라 문제 낮음 |

## 6. DB 개선 제안

코드(`repository.py`, `worker/`, `routers/`)를 기준으로 확인한 것입니다.

| # | 제안 | 근거 | 우선순위 |
| --- | --- | --- | --- |
| 1 | **사용하지 않는 `survey` 테이블 정리** | 코드에서 `survey`에 쓰는 곳이 없습니다. 가감요소 답은 `analysis.confirmed`에 들어가고, 사전 설문은 제거됐습니다(`engines.py`는 `no_survey: True`). `db.py`가 "알려진 스키마인지" 검사할 때 이름만 참조합니다. 쓰지 않을 거면 마이그레이션으로 제거, 가감요소 답을 따로 집계하려면 이 테이블로 옮기는 것도 선택지입니다. | 중 |
| 2 | **`report` 테이블 보류 표시** | 서버 PDF가 501이라 아무 데서도 쓰지 않습니다. 서버 PDF를 만들지 정해지면 유지/삭제를 결정하세요. | 낮음 |
| 3 | ~~저장 동의 영상의 만료일 정책~~ | **반영됨(2026-10-20).** 저장 동의한 비식별 영상은 90일(`RETENTION_DAYS`) 뒤 삭제합니다. | 완료 |
| 4 | ~~분석 결과 보관 기간과 삭제 경로~~ | **반영됨(2026-10-20).** 세션 2시간이 지나면 분석 결과와 사고 제목을 DB에서 지우고 조회는 즉시 `410`. 사용자가 바로 지우는 `DELETE /accidents/{id}`(결과 지우기)도 추가했습니다. | 완료 |
| 5 | **가감요소 답변을 검색 가능하게** | 답이 `analysis.confirmed` JSON 안에만 있어, "가장 자주 틀리는 질문" 같은 집계는 JSON 쿼리가 필요합니다. 성공 지표(사용자 수정률, 가감요소 커버리지)를 낼 계획이면 `scene`의 AI 판단과 `confirmed`의 사용자 값 차이를 비교하는 뷰나 컬럼을 고려하세요. | 중 |
| 6 | **사용자 수정 여부 기록** | 성공 지표 "사용자 수정률"을 재려면 AI가 제안한 유형과 사용자가 확정한 유형을 비교해야 합니다. `scene.situation.default_index`와 `confirmed`로 계산은 가능하나, 컬럼(`user_changed`)이 있으면 집계가 쉽습니다. | 낮음 |
| 7 | **`job` 정리** | 완료·실패 행이 계속 쌓입니다. 일정 기간 뒤 삭제하는 작업을 `cleanup`에 추가할 수 있습니다. | 낮음 |
| 8 | **`pgvector`는 보류** | 마이그레이션 첫 줄에 "필요해지면 별도 마이그레이션"으로 적혀 있습니다. 판례 유사도 퍼센트는 의미 없다는 결정이 있어 지금은 필요 없습니다. | 해당 없음 |
| 9 | **마이그레이션 절차** | 공용 DB에서는 자동 적용하지 않습니다. 새 파일이 생기면 한 사람이 팀에 알리고 `python -m app.migrate --apply`로 적용합니다. 위 제안은 모두 **새 번호의 마이그레이션 파일**로 만들고, 적용 전에 팀 공지를 하세요. | — |
